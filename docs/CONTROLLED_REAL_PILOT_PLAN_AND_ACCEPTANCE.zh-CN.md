## 1. 目的与完成定义

本试点验证从一个受限研究问题到可审计文献调研工件的链路，重点确认：

1. 官方 SciVerse SDK、DeepSeek、MinerU、公开 PDF 替代路由与本地授权 PDF 路由的配置和授权门禁实际生效；
2. 检索、人工筛选、正文访问确认、解析、Source Map、证据审核之间不能互相绕过；
3. 私有全文、URL、原始提供商响应、token、绝对路径不进入运行工件、DSH 输出、UI 投影或发布包；
4. 未完成审核时，工作流如实显示 `waiting_human_review`，不产生科学结论。

自动试点完成不等于论文结论已被证实，也不等于私有运行工件可公开发布。代码与公开文档可按使用者已有的 GitHub 推送授权提交；第 8 阶段未全部通过前，不得发布研究结论或私有试点数据。

## 2. 角色、授权与硬性边界

| 角色 | 允许操作 | 禁止操作 |
| --- | --- | --- |
| 使用者/审核者 | 提供问题范围、填入 `.env`、批准计划、筛选全部候选、提供合法来源 URL、审核 Source Map 与 EvidenceCard、决定是否发布。 | 把 token、正文或受限 URL 填入 Git、UI 或运行工件。 |
| CosMatter 本地领域层 | 验证配置存在性、写入脱敏工件/回执、执行已批准的有界调用、计算哈希、阻断越权流程。 | 回显密钥、自动扩大检索、把模型草案视为证据。 |
| DSH bundle | 通过 `127.0.0.1` 调用允许的 loopback API，提供任务、策略、检索元数据、筛选、MinerU 任务元数据与图查询。 | 读取正文、读取文件系统、上传本地文件、接受证据、调用 shell。 |
| 浏览器本地 PDF 入口 | 在候选已被人工纳入后，让使用者选择一份有权处理的本地 PDF，并在明确同意后交给 loopback API。 | 登录校园系统、保存账号/Cookie/VPN/代理信息、后台选择文件，或把 PDF 当作已经审核的证据。 |

每次真实外部调度均要求当前任务范围内的显式授权。授权只允许命名调用，不构成科学证据接受。任何阶段发现密钥、全文或 URL 已进入运行目录，应立即停止试点、隔离运行目录并重新开始。

## 4. 阶段 0：本地基线与安全检查

### 执行

1. 在新的 PowerShell 终端进入 `D:\CosMatter\development\CosMatter`，运行 `./scripts/acceptance.ps1`；它只执行本地测试、打包与合成回放，不读取 `.env` 或调用提供商。若需要保留本次基线的脱敏验收收据，可显式附加 `-ReportPath <新建的 .json 路径>`；收据只记录步骤状态与耗时，且默认拒绝覆盖已有收据。schema `1.1` 收据含内容 SHA-256，可用 `./scripts/verify-acceptance-receipt.ps1 -Path <收据路径>` 离线验证。若只需诊断 Python 套件，可使用 `./scripts/test-all.ps1`。
2. 确认 `python`、`git`、`gh`、`dsh`、`sciverse`、`xelatex`、`bibtex` 可执行。
3. 运行 Python 全量测试、前端类型检查与测试、七个 DSH bundle 测试。
4. 运行 Git 空白错误检查与敏感字段扫描；扫描结果不得输出 `.env` 内容。

### 验收标准

- Python 测试、前端测试、七个 bundle 测试均以退出码 `0` 结束；
- `git diff --check` 无空白错误；
- 运行目录、`case-data`、`.env`、token、完整正文和 URL 不在待提交文件中；
- 失败时只修复本地代码或配置，不调用任何外部提供商。

## 5. 阶段 1：配置验收

### 执行

1. 使用者在受保护的工作区 `.env` 填入已拥有的值；不要在聊天、终端回显或提交中粘贴值。
2. 运行 `cosmatter check-config`（或等价本地状态检查）。
3. 仅记录“已配置/未配置”，不记录 token 长度、前缀、请求头或原始环境变量。

### 验收标准

- SciVerse、DeepSeek、MinerU 的状态与使用者预期一致；
- 输出中没有 `API_KEY`、`TOKEN` 的实际值，亦没有完整 URL、请求头或 `.env` 路径；
- 缺少任意本试点需要的服务时，该服务的阶段保持 `blocked`，其余不相关阶段不得被伪报为完成。

## 6. 阶段 2：任务、检索计划与授权

### 执行

1. 创建一个 Mission Brief，明确研究问题、材料、性质、样品范围和任务 ID。
2. 可选：在精确的任务范围外发同意与 DeepSeek 请求同意下，生成 `deepseek-v4-flash` 的不可信检索草案。
3. 由使用者批准至多两条主检索式和一条反例检索式；草案本身不能成为批准计划。
4. 明确记录 SciVerse 元数据检索所需的任务范围外发同意与元数据提供商同意。

### 验收标准

- `mission.json` 与已批准计划属于同一 `mission_id`；
- 检索式总数不超过 3，且存在至少一条反例或边界检索式；
- 模型输出（若存在）标记为 `untrusted_draft`；
- 缺少任一精确同意时，外部调度被拒绝且没有提供商回执。

## 7. 阶段 3：有界 SciVerse 检索

### 执行

1. 每次只执行批准计划中的一条检索式，设置有界 `top_k`。
2. 使用官方 `sciverse==0.7.1` 的 `AgentToolsClient.semantic_search`，不自行拼接鉴权请求。
3. 为每一次成功或失败写入脱敏回执：提供商、操作、状态码、请求 ID 摘要、查询哈希和候选数。
4. 写入仅含候选元数据的 `retrieval_candidates.json`；不保存段落正文或原始响应。

### 验收标准

- 执行次数不超过已批准的 3 条检索式；
- 每个 provider-linked 候选都有可审计的回执链接；
- 候选工件不包含正文、token、完整请求 URL 或原始 HTTP 响应；
- 部分来源失败时，保留成功候选并如实记录失败；所有选定来源均失败时，试点停止在检索阶段。

### 起始页自动检索的多源门禁

- 前端首次取得经过结构校验的本机能力快照时，选择全部当前可用的书目来源；不得隐藏地只默认 Crossref。后续能力刷新只保留仍可用的人工选择，不得重新勾选使用者已取消的来源。
- 使用者勾选一次性授权前，起始页必须明确列出本次会收到任务边界的服务名；请求实际携带的 `sources` 必须与可见清单一致。
- 每个来源独立记录完成或失败。一个来源失败时，其余来源的成功候选仍可进入人工筛选；只有全部可见来源失败时才进入失败空壳。
- 真实浏览器回归已覆盖中文 BiFeO3 温度与条件差异问题：DeepSeek 候选通过问题锚点校验；授权区列出 Sciverse、OpenAlex 与 Crossref；Sciverse 返回候选、OpenAlex 正常空结果、Crossref HTTP 406 的组合最终以部分成功进入文献星图，并保留 Crossref 来源告警。该验收只证明路由和失败隔离，不证明候选相关性或科学结论。

## 8. 阶段 4：完整人工候选筛选

### 执行

1. 生成候选筛选模板。
2. 使用者必须对当前全部候选逐项填写 `include_for_fulltext`、`exclude` 或 `needs_metadata_review`。
3. 仅选择一篇最适合试点的候选进入下一阶段；其余候选保持元数据状态。

### 验收标准

- 每个 `document_id` 恰有一个决定；
- 筛选工件与当前候选集指纹一致；候选集变化后旧筛选自动无效；
- 筛选工件不保存标题、摘要、正文或自由文本理由；
- 筛选不完整时，读取正文、MinerU 提交和证据摄取均必须失败。

受委托自动试点只能另写 `automated_trial_candidate_screening.json`，并将所有未点名候选保持为 `needs_metadata_review`。它可打开隔离的解析试跑，但不使正式筛选阶段完成。

## 9. 阶段 5：单篇有界内容访问确认

### 执行

1. 若候选有上游明确的 `is_content_accessible=true` 声明，记录为上游访问声明；对 Sciverse 语义检索命中，SDK 契约中的非空 `doc_id` 同样表示可调用 `read_content` 的全文 artifact。显式 `is_content_accessible=false` 始终优先拒绝。
2. 若字段缺失或为 `false`，不得修改候选 JSON；只有完成筛选后，使用者可显式执行 `sciverse-read-context`。
3. 该命令至多读取一篇文献的一个有界窗口，写到运行目录外的新 `.txt` 或 `.md` 审阅文件。
4. 成功后，运行目录仅生成 `content_access_confirmations.json`，其中只有任务 ID、候选集指纹、文献 ID、回执 ID 和正文 SHA-256。
5. 对出版社 403 或机构订阅全文，不得让 DSH/Agent 接管校园登录。使用者可在正常浏览器中自行登录并依许可下载 PDF；完成候选筛选后，再从前端为同一候选选择该本地文件。校园账号、密码、Cookie、VPN 与代理配置不进入 CosMatter。

### 验收标准

- 没有人工完整筛选时，SDK `read_content` 绝不被调用；
- 确认工件不包含正文、URL、token、请求 ID 或审阅文件路径；
- 审阅文件位于运行目录外，且必须是新建文件；
- 候选历史改变后，哈希确认失效；
- 成功确认只证明受控读取成功，不证明论文结论或全文使用权。
- 本地 PDF 路线必须绑定当前任务中已人工纳入的同一候选；仅把文件拖入起始页创建独立解析任务，不能获得候选证据资格；
- 本地文件选择由使用者在浏览器中显式完成，DSH 无文件系统或校园会话权限。

## 10. 阶段 6：单篇 MinerU 解析任务

### 执行

1. 远程路线：使用者提供同一候选的、合法可处理的无凭据 HTTPS 来源 URL。
2. 本地路线：使用者在正常浏览器中自行取得 PDF，在候选筛选结果重新载入后点击“为此候选选择授权 PDF”，并确认有权处理且同意发送至 MinerU 云端。loopback API 只接受单个 PDF、最大 200 MB，并以内容哈希建立幂等任务身份。
3. 两条路线都要求与当前任务相符的外发、文件处理和私有内容授权；前端本地路线以提交时的明示复选框作为当前文件的授权动作。
4. 每次只提交一篇候选，并按需轮询任务；远程路线默认不下载或保存 MinerU 原始输出，完成后可显式调用 `mineru-fetch-markdown` 将唯一 Markdown 成员写到运行目录外的新私有文件；本地路线把完整 Markdown 留在本机私有存储，只向 UI 投影状态、哈希与计数。两条路线都不得把 ZIP、结果 URL 或 Markdown 写入 run。
5. 运行内只保存任务状态、候选/文献 ID、来源或 PDF 内容哈希、任务 ID 哈希、模型版本与脱敏回执；本地私有存储与 run 分离。

### 验收标准

- 候选必须同时满足完整筛选，以及上游访问声明、当前哈希确认或当前浏览器明确选择的本地授权 PDF 三者之一；
- 远程路线缺任一授权、非 HTTPS URL、带凭据 URL、localhost/内网 URL 都必须被拒绝；本地路线缺明示同意、候选绑定、PDF 签名或大小校验必须被拒绝；
- DSH 和 UI 输出不含 URL、正文、解析结果或任务 ID 明文；
- `source_parse_tasks.json` 与 provider receipt 的哈希链接审计通过；
- 如使用 `mineru-fetch-markdown`，其回执必须只含 Markdown 哈希和字节数，且私有输出文件不在 run 内；
- 同一 PDF 在提交响应丢失后必须复用原任务身份；先刷新本机状态，不重复上传；
- 若解析失败，记录失败状态并停止，不自动换 URL、文件、重试或扩大范围。

实现与回归入口：`frontend/src/CandidateScreeningPanel.tsx` 只对已经提交并重新载入的 `include_for_fulltext` 候选开放文件选择；`frontend/src/Launchpad.tsx` 显示 MinerU 云端发送同意；`src/cosmatter/local_api.py` 再次检查候选筛选、PDF 头、大小与幂等身份。`tests/test_local_api.py` 覆盖候选绑定、越权候选拒绝、响应丢失后的同任务重试及私有 Source Map 门禁。

## 11. 阶段 7：人工 Source Map 与证据审核

### 执行

1. 使用者在运行目录外、依其合法访问权限审阅解析结果。
2. 创建最多 12 条短片段的人工 Source Map；每条含定位、类型、短引文和选择理由。
3. 生成 EvidenceCard 草案，并逐条由使用者审核主张、条件、文献定位、立场和证据充分性。
4. 只有审核为 `accepted` 的 EvidenceCard 才可进入分歧分析、图谱或报告。

如仅为已授权的端到端技术试跑，自动选择必须来自哈希绑定的私有 MinerU 候选池，并保存为独立的自动试点 Source Map；逐条判断只允许 `directly_supported`、`qualified_by_source` 或 `not_supported`，且不得产生正式材料事实或 EvidenceCard。

### 验收标准

- 每个短引文与 Source Map 中同一文献、同一定位精确匹配；
- 不存在 Source Map 时，结构化解析路径上的证据摄取被拒绝；
- 模型草案、未审核摘录和候选元数据不得被统计为科学证据；
- 每张被接受 EvidenceCard 都可回链至人工审核的定位片段。

## 12. 阶段 8：审计、报告与发布判定

### 执行

1. 生成工作流就绪度、来源回执审计、证据来源审计、报告证据审计和脱敏 UI 投影。
2. 运行 `cosmatter audit-sensitive-artifacts --run-id <run_id>`；该命令只保存命中类别与数量，绝不回显 URL、正文、凭据或私有路径。
3. 生成研究报告、条件分歧矩阵和证据图；它们只消费已接受证据。
4. 记录成本、耗时、失败模式、人工审核意见及未解决限制。
5. 使用者单独决定：关闭试点、继续迭代，或授权 Git 提交/推送/公开发布。

### 验收标准

- `workflow_readiness.json` 的每个阶段状态与实际工件一致；
- 报告中每条证据主张可回链到已接受 EvidenceCard 和定位；
- `sensitive_artifact_audit.json` 的 `is_clean=true`，且敏感扫描无 token、完整正文、受限 URL、原始提供商响应、绝对私有路径；
- 没有明确人工发布批准时，不执行 Git 提交、GitHub 推送、发布包上传或公开链接创建；
- 最终试点结论必须标明：验证的是工作流与门禁，不是材料科学结论的真实性。

## 13. 停止、恢复与复测规则

| 情况 | 立即动作 | 恢复要求 |
| --- | --- | --- |
| `.env` 或 token 疑似泄露 | 停止调用；撤销/轮换相关 token；隔离受影响日志。 | 完成凭据轮换、敏感扫描和人工确认。 |
| 正文、URL 或原始响应进入运行工件 | 停止试点；不发布该运行。 | 修复持久化路径，新增回归测试，并从干净运行重新开始。 |
| SciVerse 无可读候选 | 保持 `waiting_human_review` 或 `blocked`；不伪造字段。 | 人工筛选后只可执行一次受控内容确认，或联系提供商核对权限。 |
| 出版社 403 / 机构订阅 | 不绕过访问控制，不把校园凭据交给 DSH 或 Agent。 | 使用者在正常浏览器中依许可取得 PDF；完整筛选后通过候选绑定的本地 PDF 入口并重新确认 MinerU 外发。 |
| MinerU 失败 | 记录失败与回执；不自动切换来源。 | 使用者明确提供新的合规来源并重新授权。 |
| 证据审核未通过 | 保留为草案/拒绝状态。 | 修改或补充人工审核，不自动升级。 |

## 14. 试点结束交付物

试点结束时应交付以下脱敏材料：

- 任务简报、已批准计划、候选元数据与完整筛选决定；
- 授权回执、提供商回执摘要、内容访问确认摘要与解析任务状态；
- Source Map、审核后的 EvidenceCard、分歧矩阵、图投影和报告证据审计；
- 工作流就绪度、测试摘要、敏感扫描摘要、成本/失败模式记录；
- 一份人工签署的“继续/停止/发布不批准”决定。

任何正文、受限 URL、token、原始解析响应或私有缓存都不属于上述交付物。
