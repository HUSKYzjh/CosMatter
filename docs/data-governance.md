# CosMatter 数据治理与发布边界

本规范说明 CosMatter 中哪些数据可以进入仓库、运行工件、提交包和浏览器 UI。它是工程边界，不替代论文版权、数据库许可、机构数据政策或人工审查。

## 1. 数据分级

| 类别 | 示例 | 允许位置 | 禁止位置 |
| --- | --- | --- | --- |
| 公开工程资料 | 源代码、Schema、无密钥示例、聚合测试结果 | Git 仓库与提交包 | 不适用 |
| 受控运行元数据 | 任务 ID、状态、计数、哈希、审计结论 | 本地 `runs/<run_id>/`、经门禁的 UI/提交投影 | 不得含全文、URL、提示词或凭据 |
| 受限研究材料 | PDF、机构全文、解析 Markdown、长引文、人工批注 | 授权的私有工作区 | Git、运行工件、UI、提交包 |
| 认证与个人数据 | API token、cookie、Authorization header、校园账号、个人身份资料 | 本地 `.env` 或受管密钥存储 | 所有仓库文件、日志、报告、收据和 UI |

“可访问”不等于“可再分发”。上游允许读取的内容仍只能按其许可和本规范使用。

## 2. 运行工件的最小化原则

运行目录只保存完成门禁所需的最小元数据。提供方收据以请求摘要、时间、状态、计数和摘要哈希证明一次受控调用；它们不保存原始查询、响应、授权头、全文或请求体。解析任务同样只保存哈希化的任务与来源关联。详见 [提供方收据](provider_receipts.md)。

Source Map 是从已授权材料中由审阅者挑选的短片段定位记录。它是后续人工审核和证据卡的入口，而不是将论文全文导入仓库的通道。材料事实草稿、证据卡和 Research Gap 候选均不能绕过来源定位、条件记录和人工审核门禁。

## 3. 发布与导入边界

`export-ui` 只投影白名单字段和聚合审计状态；浏览器不会读取 `.env`、运行事件原文或外部提供方。`build-final-submission-package` 只打包白名单源码和已验证的报告工件。

可交换的运行包也不是任意 JSON 容器。导入前会校验任务身份、每个工件的哈希绑定和数据类型，并拒绝私有路径、URL、认证字段、全文相关字段及非 JSON 值；恢复在临时目录完成，全部验证通过后才原子发布为新运行目录。收到拒绝时，应修正源工件，而不是删除门禁或手工修改审计结果。

## 4. 保留、删除与外部披露

私有全文、PDF、解析缓存和人工笔记的保留期限由材料许可、机构规则与研究负责人决定；CosMatter 不自动删除这些外部数据。需要撤销或清理时，先在私有工作区处理原始材料，再保留足以说明工程状态的非敏感聚合记录。

每次正式外部资源使用都应记录服务/数据库、访问日期、版本或模型标识、适用条款与授权状态，但不得把密钥、原始请求或受限内容写入披露。命令和提交准备规则见 [复现说明](../REPRODUCIBILITY.md)。

## 5. 发现敏感信息时

立即停止分享相关文件，撤销或轮换受影响凭据，清理公开副本，并通过私下渠道通知维护者。具体响应步骤见 [安全政策](../SECURITY.md)。
