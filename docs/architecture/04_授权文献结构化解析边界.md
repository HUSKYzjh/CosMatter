# 授权文献结构化解析边界

本模块是 CosMatter 的“文献定向仪”入口：它只把已经通过
上游 `is_content_accessible=true` 声明或当前哈希内容确认门禁的候选文献，送入用户明确给出的 MinerU 远程
HTTPS 来源。它不是全文缓存、网页代理或自动证据生成器。

## 已实现的受控路径

```text
approved candidate (upstream access declaration or current hash-only confirmation)
  -> user supplies one public-looking HTTPS source URL
  -> MinerU v4 asynchronous task
  -> source_parse_tasks.json (task state + URL SHA-256 only)
  -> reviewer-selected bounded source-map -> later evidence-draft workflow
```

`mineru-submit-url` 与 `mineru-poll` 不下载解析结果，不保存 Markdown、
JSON、CDN 结果链接或源 URL。浏览器 UI 也不读取该任务账本。这样，文献
结构化能力仍在后端的授权范围内，不能绕过现有的短引文、定位信息和人工
审核门禁。

## 命令

以下命令仅在上级 `.env` 已由使用者配置 `MINERU_API_TOKEN` 时才会实际
访问 MinerU；实现和测试不会读取或展示密钥。

```powershell
./.venv/Scripts/python.exe -m cosmatter mineru-submit-url `
  --run-id bfo_live_001 --document-id sciverse_document_id `
  --source-url "https://publisher.example/authorized-paper.pdf"

./.venv/Scripts/python.exe -m cosmatter mineru-poll `
  --run-id bfo_live_001 --document-id sciverse_document_id

# 只提交人工审阅后选出的 1–12 个短片段；不会读取 MinerU 原始输出
./.venv/Scripts/python.exe -m cosmatter record-source-map `
  --run-id bfo_live_001 --document-id sciverse_document_id `
  --input ./reviewed_source_selection.json
```

`reviewed_source_selection.json` 必须仅包含同一 `document_id` 与最多 12 个
`segment_id + locator + kind + quote` 片段；每段 quote 上限 500 字符。系统仅在
对应 MinerU 任务状态为 `done` 时写入 `source_map.json`，并把 task ID 以哈希
形式关联。片段本身留在本地运行目录，绝不进入 UI JSON 或审计日志。

允许条件：候选文献属于同一运行、其具有上游 `is_content_accessible=true` 声明或当前哈希内容确认、来源为
无凭据的 HTTPS URL；客户端拒绝 `http`、localhost、`.local` 与显式私有
IP。DNS 重定向/服务端请求伪造防护仍应由文献来源与 MinerU 服务端承担，
因此不应提交内网或临时凭据 URL。

## 采用的官方契约

- 云端 v4：`POST /api/v4/extract/task` 提交 URL 和 `model_version`，随后
  `GET /api/v4/extract/task/{task_id}` 轮询。
- 后续若使用本地部署，可适配官方 `mineru-api` 的 `POST /tasks`、
  `GET /tasks/{task_id}` 与 `GET /tasks/{task_id}/result`；本项目当前没有
  启动本地服务，也不拉取结果。

该阶段完成的是“授权解析任务溯源”与“人工复核的 source-map”，但二者都不是已验证的科学证据。下一阶段才可由人工基于 source-map 生成现有 `ingest-evidence` 所需的窄证据草稿。

## 本地下载结果的人工复核池

如果操作者已按学校账号、出版社条款或 MinerU 控制台的既有流程，在**运行目录以外**取得某篇已完成任务的 UTF-8 Markdown 结果，可使用离线命令 prepare-mineru-markdown-review 将其切分为最多 48 个、每段最多 500 字符的候选片段。该命令要求 --input 和新建的 --output 都在运行目录外。

对于已记录为 `done` 的 MinerU 任务，也可显式执行 `mineru-fetch-markdown --output <new-private.md>`：客户端只在内存中读取服务端返回 ZIP 的唯一 UTF-8 Markdown 成员，并将其写入运行目录外已有目录中的新文件。运行内仅追加文献 ID、任务/来源哈希、Markdown SHA-256 与字节数的回执；结果 URL、ZIP、Markdown、私有输出路径及任何摘录均不进入运行工件、UI 或 DSH 投影。

该命令不读取 .env、不调用 MinerU、不会把 Markdown、全文路径、原文片段或解析结果写入运行目录、事件日志或 UI；输出的候选池应存放在受控的本地位置。它的 trust_status 为 private_unreviewed_mineru_markdown_candidate_pool_not_source_map，因此不是证据、更不是可直接供模型使用的语料。

复核者可先运行 create-mineru-source-map-review-template，得到不含摘录原文、但保留候选片段 ID 与摘录哈希的私有模板。人工将模板的 trust_status 改为 human_reviewed_source_map_pool_selection，并仅为 1–12 条已核对片段设置 selected=true 与具体 reason；随后以 record-source-map 的 --review-pool 参数提交模板。系统会同时核验任务哈希、Markdown 哈希、所有候选片段哈希及选中数量，最终 Source Map 才保留所选短摘录。候选池并非新的绕过入口：record-source-map 仍会核验任务已完成、候选文献已获准访问且已通过全文筛选。

如用户明确要求仅做端到端受控试点，可使用单独的 `--allow-delegated-automated-trial` 开关配合 `automated_trial_candidate_screening.json`。它只接受另行标记的自动试点筛选，产生 `delegated_automated_trial_source_map_not_scientific_evidence`，不覆盖或伪装为 `human_reviewed_parser_selection`。任何正式事实抽取、EvidenceCard、报告与提交路径仍只接受人工审核 Source Map。

## source-map 与证据门禁

当同一文献已具有 `source_map.json` 时，`ingest-evidence` 的 `quote` 与
`provenance.locator` 必须精确匹配其中一个人工复核片段；改写、摘要或错页
定位会被拒绝。尚未建立 source-map 的既有手动录入流程保持可用，但一旦采用
结构化解析，就不能绕过这道回溯门禁。
