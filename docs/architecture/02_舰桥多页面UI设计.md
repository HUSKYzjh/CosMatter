# CosMatter 舰桥多页面 UI 设计

## 目标

静态 UI 是本地 Python 运行时产出的已脱敏工件的阅读、核验和规划表面；它不是 LLM
控制台、全文阅读器或 API 代理。视觉上采用“星际舰桥”隐喻：状态像航程、设施像舰载
仪器、证据像可追溯信号，但不把装饰性星图误表示为科学因果图。

三套本地主题均由同一设计令牌实现：`dark`（深空）、`light`（日间观测）和 `eye`（低
对比护眼）。主题仅存在浏览器偏好中，不改变工件内容或任何运行状态。

## 页面与任务边界

| 页面 | 本地功能 | 输入 | 明确不做 |
| --- | --- | --- | --- |
| `index.html`：任务舰桥 | 导入工件、查看任务/舰队、筛选已批准证据、展开条件矩阵 | 用户明确选择的 `ui.json` | 扫描 `runs/`、读取 `.env`、直接检索或调用模型 |
| `workflow.html`：研究工作流 | 显示六站航程、发布门禁和与当前工位对应的本地 CLI 提示 | 同一 UI JSON | 在浏览器执行命令、跳过审核或改变任务状态 |
| `network.html`：星图网络 | 从任务、已批准证据、条件簇及未知项派生可点击 SVG 关系图 | 同一 UI JSON | 将边解释为因果、引用影响力或自动发现结论 |
| `extensions.html`：研究拓展 | 选择跨库核验、实验、计算或评测设施，下载一个标记为不可信的规划草案 | 内置公开模板 | 提交 HPC/实验、下载论文、调用材料数据库或批准假设 |

## 研究工作流映射

```text
问题接令 → 审批航线 → 主/反例检索 → 可定位证据 → 条件与反证核验 → 报告交付
                          ↑                                       │
                          └──────── 人工退回规划（有理由） ───────┘
```

`workflow.html` 只投影上述状态。实际执行仍限定为 `approve-plan`、
`execute-plan-query`（主查询或 `--counter`）、`ingest-evidence`、
`diagnose-conditions`、`build-report` 和 `export-ui`；每个命令都由 Python
侧门禁、审计工件和单元测试约束。

## 星图语义

- 任务锚点连接已批准证据与条件簇；条件簇连接其支持/反驳证据和未知项。
- 证据节点显示的定位信息仅为 `document_id + locator`，不导出原始全文或未批准长摘录。
- 节点筛选是显示过滤，不能改变导出的工件、审核结论或科学事实。

这借鉴科学前沿工具的渐进披露：先问题和路径，后关系和证据，再转入研究拓展；同时保留
CosMatter 的人工审核和条件优先原则。

## 后续实现顺序

1. 为四页补充浏览器级测试：主题切换、文件导入失败路径、键盘节点选择和窄屏布局。
2. 已将 Python 运行记录投影为经脱敏的固定动作时间线；后续只可扩展白名单动作，避免暴露 `events.jsonl` 原文。
3. 仅当 UI 工件契约稳定后，评估一个监听 `127.0.0.1` 的只读服务；仍不得代理 LLM、
   文献全文或第三方检索 API。
4. 在服务端新增经批准的图布局、材料数据库核验或计算调度之前，先扩展工件 Schema、
   审计和冻结测试；前端不得自行推断这些字段。
