# 提交级执行清单

build-submission-execution-manifest 为一个已存在的 CosMatter 运行生成 submission_execution_manifest.json。它用于在答辩、初赛文档或复跑交接时回答一个有限的问题：该 run 中哪些工作流阶段和审计工件确实存在？

它不运行模型、不调用 Sciverse、MinerU 或其他外部 API；也不生成研究结论。

## 运行

在 CosMatter/ 目录中执行：

~~~powershell
.\.venv\Scripts\python.exe -m cosmatter build-submission-execution-manifest `
  --run-id bfo_90_v1
~~~

输出固定在：

~~~text
runs/bfo_90_v1/submission_execution_manifest.json
~~~

建议在冻结评测、生成报告和运行 audit-workflow-readiness 后再执行。重新执行会根据当前 run 工件更新该快照。

## 清单包含什么

- Mission 的材料、性质、范围与 run 内工作流阶段状态；
- 计划、检索、筛选、解析任务、证据核验、条件矩阵、Gap、报告、人工评测，以及外部资源披露、势函数边界计划、执行协议、外部结果比较和待批准后续任务等允许工件的“是否存在、字节数、SHA-256”；
- 审计事件总数与按事件类型聚合的计数；
- 供应商回执总数与按“供应商：操作”聚合的计数；
- 将上述输入稳定组合后的摘要哈希；
- 已完成真实评测时的运行记录、失败案例与成本/延迟工件只以文件名、大小和哈希进入执行清单；最终提交包仅在一致性门禁通过后才可附带它们的聚合 JSON。
- 清晰的边界声明。

这使评审可以区分“系统真正执行的受控步骤”和“仅在方案里声称的能力”。

## 清单刻意不包含什么

以下内容不会被复制进清单：

- API 密钥、环境变量、请求头；
- 原始查询、查询摘要、提示词；
- PDF、Markdown 全文、Source Map 引文、表格或图片；
- 本地文件路径、URL、附件键；
- 服务商请求 ID、任务 ID；
- 逐篇文献判断、专家身份或人工标注明细。

详情仍保留在受控本地工件中供团队核查；公开提交前必须依据文献许可、学校账号约束和赛事规则再次筛选。

## 如何解读

清单的存在只能证明受限 run 内的工件和记录存在且可校验；它**不能**证明：

- 搜索覆盖了全部材料文献；
- 文献事实、抽取结果或科学推论为真；
- Gap 在全球范围内新颖；
- 模型或人工评测已经达到某项性能；
- 第三方服务的原始响应真实性。

因此应与 workflow_readiness.json、证据溯源审计、候选回执审计、人工金标准和实际报告一同审阅。
